# 幕间（MuJian）前端代码审查报告

**审查范围**：`frontend/src` 下全部 Svelte 路由、组件与 lib 模块
**审查方式**：静态代码审查（逻辑 / 交互 / 展示），未运行构建
**重点维度**：① 多输入元素搭配与交互 ②「← 返回」按钮行为 ③ 多剧种对剧目剧种的污染 ④ 多子项布局 ⑤ 折子添加流程 ⑥ 其他问题

---

## 一、核心问题（高严重度）

### 1. 「← 返回」会丢失首页筛选状态 → 误入未筛选页面【维度②】
**位置**：`BackLink.svelte:8-17` 与 `routes/+page.svelte`（首页）

- 首页筛选（分类/城市/年份/月份下拉 + 搜索框）是**纯前端 `$state`**（`filters`，`+page.svelte:15`），过滤由 `load()` 发 API 完成（`+page.svelte:132-144`），**从不写入 URL query**。
- 用户在筛选后的列表点开某条记录 → 进入 `/records/123`（新 URL，历史栈前一项是 `/`，且 query 为空）。
- 在记录详情点「← 返回」→ `history.back()` 回到 `/` → 组件 `onMount` 从 `$page.url.search` 读筛选（`+page.svelte:189-202`），query 为空 → **筛选被清空，落到未筛选列表**。这正是"误入未筛选页面"。

**不一致之处**：通过记录详情的"剧种/城市"胶囊进入的是带 query 的 URL（`/?category=昆剧`），此时返回能保留筛选；而用首页筛选栏筛选则不保留。两种筛选入口返回行为不一致，用户预期混乱。

**建议**：把首页筛选同步进 URL query（`goto('?...', { replaceState:true })` 或 `pushState`），使 `history.back()` 能还原筛选与滚动；或在返回时从 `sessionStorage` 恢复 `filters`。

---

### 2. 多剧种演出会污染剧目剧种，剧种标记实为「手动维护」【维度③】
**位置**：`routes/dramas/[id]/+page.svelte:47,174-176,187`、`RecordForm.svelte:146-172`

- 剧目的 `categoryNames` 由后端**按关联演出自动聚合**而来（详情页提示："留空剧种 = 按关联演出自动统计；手动填写可修正拼盘演出带来的偏差"）。
- 一旦某剧目出现在**多剧种 / 拼盘**演出中，该场演出的所有剧种都会被聚合进剧目 → 剧目被错误标记为其他剧种。这正是"多剧种单次演出错误污染剧目剧种显示"。
- 更危险的是 `RecordForm` 内联编辑：`startDramaEdit` / `saveDramaEdit`（`RecordForm.svelte:146-172`）允许在**编辑某条演出时直接改写该剧目的 `name` 与 `categoryNames`**，且 `api.updateDrama` 是全局写。为修某场演出的剧种而改动，会**污染该剧目在所有演出中的剧种展示**——属于隐蔽的 footgun。
- 现状被迫"手动修正"（`dramas/[id]` 的"编辑"可手动填写剧种覆盖聚合），说明剧种标记本质是人工维护、易错。

**建议（评估方向）**：
- 剧目 `categoryNames` 应作为**剧目档案的权威属性**由用户显式设定，而非从演出反向聚合；或聚合只取"该剧目被单独演出时的剧种"，排除拼盘噪声。
- 在演出编辑表单内联改剧目名/剧种风险过高，建议**移除内联改写剧种**，仅允许在剧目详情页维护（与维度⑤一致）。

### 3. 批量编辑中「币种」下拉永远禁用，无法批量改币种【维度⑥】
**位置**：`components/BatchEditModal.svelte:241-282`

- `fields.priceCurrency / payPriceCurrency / otherCostCurrency` 默认 `enabled:false`，且界面中**没有任何 checkbox 去开启这三个 `enabled`**（只有金额字段有勾选框）。
- 三个币种 `<select>` 绑定 `disabled={!fields.xCurrency.enabled}`，因此**永远 disabled**，`save()` 里 `if (fields.priceCurrency.enabled)` 也永远不成立。
- 结论：批量改「票价/实付/其他花费」时**币种无法修改**，且保存时币种不会被提交。

**建议**：为每条费用的币种增加独立勾选框（或随金额勾选一并启用），提交时一并带币种。

## 二、重要问题（中严重度）

### 4. 返回按钮标签与真实目的地不符（多级跳转语义错乱）【维度②】
**位置**：`BackLink.svelte` + `dramas/[id]`、`artists/[id]`、`records/[id]/edit`

- `BackLink` 只要存在站内历史（`sveltekit:index>0`）就**一律 `history.back()`**，`fallback` 仅在"直接打开/刷新首跳"时生效。
- 因此在 `dramas/[id]` 上标签是"← 剧目"（`fallback=/dramas`），但当你是**从某条演出详情点进该剧目**时，点"← 剧目"实际 `history.back()` 回到了**那条演出详情**，而非剧目列表。标签承诺的目的地与实际不符。
- 同理：`artists/[id]` 的"← 演员"、`records/[id]/edit` 的"← 返回详情"在经多级跳转到达时，返回目标是"你来自的那一页"，与标签文字可能产生偏差，用户无法预知。

**建议**：标签与行为统一——要么始终 `history.back()` 且标签用中性的"← 返回"，要么在带 fallback 语义时真正 `goto(fallback)`。混合当前逻辑最易出错。

### 5. 演出编辑页无法直接添加折子，须跳转剧目详情再返回刷新【维度⑤】
**位置**：`RecordForm.svelte:911-925`

- 关联剧目后，折子仅以**复选框**呈现（`d.zhezis` 中勾选"本次演了哪些折"），**没有"新增折子"入口**；无折子时只显示提示"该剧目暂无折子（可在剧目详情页添加）"。
- 要新增折子必须离开编辑表单 → 进 `/dramas/[id]` → 添加 → 返回编辑页。流程割裂，且返回后能否看到新折子依赖组件是否重新挂载（SvelteKit 历史缓存下 `onMount` 未必重跑，`loadDramaTree` 未必刷新）。

**建议**：在每部剧目的折子区增加一个内联"＋ 添加折子"入口，调用 `createZhezi(dramaId, ...)` 后局部刷新该剧目折子列表，无需离开编辑页。

---

### 6. 一个演出含多个剧团/演员时，卡片被拉大、同行卡片随之拉伸【维度④】
**位置**：`RecordCard.svelte:51-57, 199-209`

- `.troupes`（剧团标签）使用 `flex-wrap` 但**无行数限制 / 无截断**；一场拼盘演出若有多个剧团（逗号分隔），标签会折成多行，把卡片 `.info` 撑高。
- 列表是 CSS Grid（`auto-fill, minmax(172px,1fr)`），默认 `align-items:stretch`，**同一行所有卡片等高**——个别卡片内容多会把整行拉高，造成明显留白 / 高度参差。
- 对比 `.artists` 已做单行 `ellipsis` 截断，但 `.troupes` 没有，表现不一致。

**建议**：对 `.troupes` / `.artists` 做统一截断（如 `max-height` + 超出显示"等 N 个"，或限制折叠行数），避免长内容撑破卡片。

## 三、其他问题（维度⑥补充）

### 7. 记录「分类」字段只显示第一个剧种（单值/多值模型混用）
**位置**：`records/[id]/+page.svelte:189-191`、提交 `RecordForm.svelte:551`
- 演出详情"演出信息-分类"用 `rec.categoryName`（**单值**），而角标/提交用 `categoryNames`（**数组**）。多剧种记录下该字段只显示第一个，与角标不一致。
- 提交时 `categoryName: form.categoryNames[0] || ''` 仍是单值遗留。建议统一为 `categoryNames`，清理 `categoryName` 单值字段。

### 8. 自由文本演员名为"死链"
**位置**：`RecordCard.svelte:47`、`records/[id]/+page.svelte:137-144`
- 未建档案的演员 `artist_ids[i]` 为 `undefined`，链接指向 `/artists/`（列表根），虽 `onclick` 对无 id 做了 `preventDefault`，但点击**无任何反馈**，体验差。建议无 id 时直接渲染为纯文本而非链接。

### 9. 费用币种在编辑表单是自由文本框，与批量编辑的 select 不一致
**位置**：`RecordForm.svelte:752,759,767`
- 编辑页币种是 `<input>` 自由文本（易输错如 `"cny "` 带空格），而批量编辑是 `CNY/USD` 下拉。建议统一为下拉，防止脏数据。

### 10. 编辑表单内按 Enter 可能误提交
**位置**：`RecordForm.svelte:604`（`<form onsubmit>`）
- 多数自定义输入（演员/剧目）已 `preventDefault` 拦截 Enter；但**渠道、城市、场馆、备注区之外的普通 input 按 Enter 会触发表单提交**，可能在未填完时误保存。建议显式区分"提交"入口，或对非关键 input 拦截 Enter。

### 11. 剧目搜索下拉在空查询时列出全部剧目
**位置**：`RecordForm.svelte:193-202, 948-956`
- 聚焦剧目搜索且未输入时 `showDramaList` 展开会渲染**全部可关联剧目**（可能上百条）。虽 `combo-list` 有 `max-height` 滚动，但无"仅显示前 N / 需输入才搜索"的限制，初始展开噪声大。

### 12. `autoJumpOnLoad` 在返回首页时加剧"误入未筛选"
**位置**：`+page.svelte:52-56, 201`
- 开启"定位到当前时间"偏好后，每次首页 `onMount`（包括返回）会滚动到"现在"。叠加维度①的筛选丢失，返回首页后既丢了筛选又跳了位置，落差更明显。

## 五、优先修复建议（路线）
1. **返回与筛选（#1/#4/#12）**：首页筛选同步到 URL query，使 `history.back()` 可还原；统一 `BackLink` 的标签/行为语义。
2. **剧种模型（#2/#7）**：剧目剧种改为档案权威属性（显式维护 / 智能聚合排除拼盘）；演出编辑表单移除"内联改写剧目剧种"，保留内联改名即可。
3. **折子流程（#5）**：编辑表单内联新增折子，免跳转。
4. **批量币种（#3）**：补币种勾选框。
5. **布局（#6）**：卡片多子项截断，统一卡片高度策略。
